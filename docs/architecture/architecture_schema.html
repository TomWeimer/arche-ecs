Architecture-as-Code (AaC) Verified

Arche ECS — Architectural & Dependency Flow

Strict top-down dependency flow (DAG) enforced by scripts/check_architecture.py. Lower layers never depend on or import higher layers.

Storage & Foundation Layers (0–3)

foundation: Hardware cacheline & VM page discovery, 32-bit generational handles (entity), type-erased ComponentID, and 128-bit ComponentMask.

storage: 64KB chunk page memory (chunk), entity routing (slot_map), singleton resources (resource), and deferred playback queues (command).

archetype & mutation: Contiguous chunk tables organized by component signatures with immediate transition migrations.

Runtime Subsystem Flow (Layers 4–9)

concurrency: Worker thread pool providing threads for parallel chunk dispatch.

query & sort: Chunked SoA iteration, tag filters (With/Without), and in-place spatial cycle-chasing permutation.

access, system, scheduler & plugin: Bitmask access footprint declarations (reads<T>()/writes<U>()), execution scope, topological DAG batch scheduling, and modular plugin lifecycle.

Domain Facades, World Assembly & Consumer API (Layers 10–12)

views: Domain facades (entity_view, archetype_view, resource_view, snapshot_view, system_view) decoupling consumer operations from internal storage.

world & arche.cppm: Central coordinator composing storage, scheduling, and facades into a unified C++20 module interface (import arche;).
